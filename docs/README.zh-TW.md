# SSE 即時系統監控平台
### （本文使用AI翻譯，AI可能會犯錯，望周知）
基於 **Node.js + Express + SSE** 開發的輕量級 Linux 伺服器即時監控系統，透過 Server-Sent Events（SSE）技術實現毫秒級資料推送，不需前端輪詢，低資源耗損、高即時性。

## 作者的話
這是我研究 SSE 時隨手折騰出來的一個小玩意兒。

專案一開始只做了三件事：伺服器推送時間、前端顯示本機時間、以及測試連線延遲，這些功能目前也都完整保留。

開發到一半突然想到，SSE 這種長連線不就是天生適合給前端即時推送伺服器資訊的嗎？那要推送什麼內容好呢？當然是我平時最常關注的效能參數啊！

我平常時常登入 VPS 的 SSH 後台，什麼事都不做，就開著 btop 觀察各項系統狀態，乾脆直接實作一個推送 btop 風格監控指標的功能，於是就誕生了這個專案。

整體邏輯其實相當簡單：後端依照系統平台自動選擇對應的擷取方式取得系統資訊，再透過 SSE 協定即時推送給前端展示，僅此而已哈哈😂😂😂

## ✨ 專案特色
- **即時資料推送**：基於 SSE 長連線，即時傳送系統數據
- **全方位監控指標**：CPU、記憶體、Swap、硬碟、網路、系統資訊全維度覆蓋
- **低資源佔用**：純原生 Node.js 實現，無重型依賴，伺服器資源消耗極低
- **開箱即用**：一行指令快速啟動，無需繁雜設定
- **視覺化介面**：簡潔美觀的網頁前端，隨時查看所有監控數據
- **穩定可靠**：完善的例外捕捉、連線中斷自動重新連線機制

## 📊 監控指標總覽
| 模組 | 監控內容 |
|------|----------|
| **CPU** | 使用率、核心數、1/5/15 分鐘系統負載（Windows 系統負載數值固定為 0） |
| **記憶體** | 總容量、已使用/空閒空間、使用率百分比 |
| **Swap** | Swap 分割區使用狀況、使用率 |
| **硬碟** | 掛載點、空間使用率 |
| **網路** | 即時上下行速度、累計總流量、網卡資訊 |
| **系統** | 主機名稱、系統版本、核心版本、執行時間、行程數量 |
| **網路連線** | SSE 連線狀態

## 🕒 額外特色功能
- **雙時鐘顯示**：透過 SSE 即時推送後端時間，前端精準顯示伺服器時間與本機時間
- **網路延遲即時偵測**：自動 Ping 檢測，即時顯示目前伺服器連線延遲

## 🔧 核心技術說明
### 1. Server-Sent Events (SSE)
- HTML5 規範中，由伺服器主動向客戶端推送即時資料的技術
- 相較 WebSocket 更輕量級，僅支援「伺服器→客戶端」單向傳輸
- 原生支援斷線重連，非常適合監控場景使用

### 2. 系統資訊擷取原理
- 依靠 `systeminformation` 跨平台套件擷取系統即時數據
- 自動相容 Windows / Linux / Mac，不需手動切換設定
- 統一輸出 CPU、記憶體、Swap、硬碟、網路、行程與系統版本資訊

## ⚙️ 自訂設定

開啟 `server.js`，修改 `PORT` 常數：
```javascript
const PORT = 23456; // 改為你想要使用的連接埠
```

## 📝 API 介面說明
| 介面路徑 | 請求方法 | 功能說明 |
|------|------|------|
| `/` | GET | 回傳前端監控頁面 |
| `/api/ping` | POST | 延遲檢測介面，計算網路傳輸耗時 |
| `/sse/time` | GET | SSE 即時時間推送 |
| `/sse/system` | GET | SSE 系統監控數據推送 |

## 🛡️ 安全與穩定性
- 所有系統指令執行皆加入例外處理，避免服務異常崩潰
- 客戶端斷線時自動清除計時器，預防記憶體洩漏
- 前端 SSE 中斷會自動重新連線，確保監控不中斷
- 僅讀取系統硬體資訊，無任何寫入或修改行為，安全無風險

### ⚠️ 使用注意事項
- 首次取樣的網路即時速率可能顯示為 `0`，第二次取樣後就會正常顯示
