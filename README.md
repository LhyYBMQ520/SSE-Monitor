# SSE 实时系统监控平台

基于 **Node.js + Express + SSE** 开发的轻量级实时系统监控平台，通过 Server-Sent Events（SSE）按秒推送监控数据，无需前端轮询系统指标，低资源占用、高实时性。

## 作者的话
这是我研究 SSE 时随手折腾出来的一个小玩意儿。

项目最初只做了三件事：服务端推送时间、前端展示本地时间、以及测试连接延迟，这些功能现在也都完整保留了下来。

做着做着突然想到，SSE 这种长连接不就是天生适合给前端实时推服务端信息的吗？那推点什么好呢？当然是我平时最爱盯的性能参数啊！

我平时经常登上VPS的 SSH 后台啥也不干，就开着 btop 看各种状态，干脆直接做一个推送 btop 类监控指标的功能好了，于是就有了这个项目。

整体逻辑其实很简单：后端按系统平台自动选择采集方式获取系统信息，再通过 SSE 协议实时推送到前端展示，仅此而已哈哈😂😂😂

## ✨ 项目特性
- **实时数据推送**：基于 SSE 长连接，实时推送系统数据
- **全面监控指标**：CPU、内存、Swap、磁盘、网络、系统信息全维度覆盖
- **低资源占用**：仅依赖 Express 和 systeminformation，前端无需构建工具
- **开箱即用**：一行命令启动，无需复杂配置
- **响应式界面**：桌面、平板和手机自动切换为 3/2/1 列布局
- **共享采样**：多个浏览器连接共享同一轮系统采集，避免重复消耗服务器资源
- **Linux 原生采集**：直接读取 `/proc`、`/etc/os-release` 和 `statfs`，减少第三方库调用开销
- **稳定可靠**：完善的异常捕获、连接断开自动重连机制

## 📊 监控指标一览
| 模块 | 监控内容 |
|------|----------|
| **CPU** | 使用率、核心数、1/5/15分钟系统负载（Windows系统下loadavg固定为0） |
| **内存** | 总容量、已用/空闲、使用率百分比 |
| **Swap** | Swap 分区使用情况、使用率 |
| **磁盘** | 挂载点、使用率 |
| **网络** | 实时上下行速度、累计总流量、网卡信息 |
| **系统** | 主机名、系统版本、内核版本、运行时长、进程数、当前数据来源 |
| **连接** | SSE 连接状态 |

## 🕒 额外特色功能
- **双时钟显示**：通过 SSE 实时推送后端时间，前端精确展示服务端时间和读取本地时间
- **网络延迟实时监测**：页面可见时每 3 秒通过轻量 HEAD 请求检测延迟，并以最近 5 次采样的中位数过滤偶发毛刺

## 🚀 快速开始
### 1. 环境要求
- Windows / Linux / macOS（macOS 未测试）
- Node.js 18+

### 2. 安装运行
```bash
# 1. 克隆/下载项目文件
git clone https://github.com/LhyYBMQ520/SSE-Monitor.git

# 2. 安装依赖
pnpm install

# 3. 启动服务
pnpm start
```

### 3. 访问使用
启动成功后浏览器访问：
```
http://localhost:23456
```

局域网内其他设备可通过 `http://服务器IP:23456` 访问。请确认操作系统防火墙已允许对应端口。

## 🔧 核心技术说明
### 1. Server-Sent Events (SSE)
- 服务端主动向客户端推送实时数据的 HTML5 技术
- 相比 WebSocket 更轻量，但仅支持服务端→客户端单向推送
- 原生支持断线重连，适配监控场景

### 2. 系统信息采集原理
- Linux 优先读取 `/proc/stat`、`/proc/meminfo`、`/proc/net/dev`、`/proc` 进程目录和 `/etc/os-release`
- Linux 磁盘信息优先使用 Node.js 原生 `statfs`，运行环境不支持时回退到 `df -kP`
- Windows / macOS 使用 `systeminformation` 进行跨平台采集
- 程序按运行平台自动选择采集方式，无需手动配置
- 统一输出 CPU、内存、Swap、磁盘、网络、进程和系统版本信息

## ⚙️ 自定义配置
### 修改服务端口

服务默认监听所有网卡的 `23456` 端口，可通过环境变量覆盖，无需修改源码：

Linux / macOS：

```bash
PORT=8080 HOST=127.0.0.1 pnpm start
```

PowerShell：

```powershell
$env:PORT=8080
$env:HOST='127.0.0.1'
pnpm start
```

`HOST=127.0.0.1` 表示仅本机可访问；默认 `HOST=0.0.0.0` 允许局域网设备访问。

### 修改数据推送频率

`server.js` 顶部包含两个间隔常量：

```javascript
const TIME_INTERVAL_MS = 1000;   // 服务端时间推送间隔
const SYSTEM_INTERVAL_MS = 2000; // 系统指标采样间隔
```

## 📝 API 接口说明
| 接口 | 方法 | 功能 |
|------|------|------|
| `/` | GET | 返回前端监控页面 |
| `/api/ping` | HEAD / POST | 延迟测试接口（前端使用 HEAD，POST 为兼容接口） |
| `/sse/time` | GET | SSE 实时时间推送 |
| `/sse/system` | GET | SSE 系统监控数据推送 |

## 🛡️ 安全与稳定性
- 系统信息采集均有异常兜底，单项读取失败不会中断服务
- 所有客户端共享采样任务，最后一个客户端断开后自动停止定时器
- 前端 SSE 断开自动重连，保证监控连续性
- 静态服务仅开放监控页面和图标资源，不公开后端源码及项目配置
- 监控采集为只读操作，不修改系统配置或业务数据

### ⚠️ 使用提示
- 首次采样时程序需要几秒钟收集系统信息，同时网络实时速率可能为 `0`，第二次采样后会恢复正常显示
- 项目未内置登录或鉴权。需要从公网访问时，请在反向代理层配置 HTTPS、访问控制和身份认证，不要直接暴露服务端口
